# 食널 20품목 확장 전달 자료

기존 **대파·양파·깐마늘·배추·무**는 유지하고 아래 15개 품목을 추가합니다. 로컬 PostgreSQL에서 먼저 준비한 자료이며, 이 작업에서는 공유 Supabase에 쓰지 않았습니다.

## 담당자 적용 방법

팀의 최신 WAS 저장소 루트(`pyproject.toml`과 `.env`가 있는 곳)에서 실행합니다. 압축을 푼 폴더 전체를 `handoff/siknal-20-20261128/`에 두면 아래 명령을 그대로 사용할 수 있습니다.

```bash
uv run python handoff/siknal-20-20261128/apply_catalog.py import --database-env SUPABASE_DATABASE_URL --allow-shared
uv run python handoff/siknal-20-20261128/apply_catalog.py report --database-env SUPABASE_DATABASE_URL --allow-shared
```

`.env`의 기존 `SUPABASE_DATABASE_URL`을 사용하므로 접속 정보를 파일에 추가하거나 전달하지 않습니다. 기존 운영 규칙대로 담당자 1명만 실행합니다. 적용 중에는 정기 수집·예측 배치와 겹치지 않게 합니다.

첫 명령이 **품목·별칭·소매/도매 계열 등록 → 동봉 원본 적재 → 일별 가격 정제 → 판단 지표 생성**을 수행합니다. API를 재수집하지 않습니다. `01_register_items.sql`을 별도로 먼저 실행할 필요는 없습니다. 이 SQL은 등록 내용을 검토하거나 등록만 수행할 때 사용할 수 있습니다. 스키마 변경이 없어 Flyway migration은 추가하지 않았습니다.

품목·계열 ID는 고정하지 않고 이름·시장·KAMIS 코드로 찾아 연결합니다. 기존 품목이나 코드·단위가 충돌하면 덮어쓰지 않고 실패합니다. 같은 자료로 재실행해도 품목·관측 원본·일별 가격이 중복되지 않습니다. 실행 이력은 실행할 때마다 새로 남습니다.

공유 DB 확인 시 기존 목록이 이 문서의 5개라면 `listed_items`가 **20**이어야 합니다. 새 품목에는 소매·도매 **30개 계열**이 있어야 하고, `verification.json`의 품목별 관측 수·기간과 대조합니다. DB에 다른 품목이 먼저 추가됐다면 전체 수는 달라질 수 있습니다.

## 데이터 범위와 표시 원칙

- 최신 관측 기준: **2026-11-27**. 신규 품목의 최근 1년 일별 가격과, 현재 평년 비교에 필요한 과거 5개 연도의 같은 28일 관측 구간을 우선 수집합니다. 최종 실제 기간·관측 수는 `verification.json`을 기준으로 합니다.
- **5년 전체의 연속 일별 자료를 이관하는 것은 아닙니다.** 이전 연도 차트에는 관측 구간만 나타납니다. 향후 기준일이 이동하면 과거 비교 구간을 보충하거나 전체 백필해야 합니다.
- 토·일·휴일, 미조사일과 계절 품종의 공백을 임의로 채우지 않습니다. 과거의 단위가 현재와 다르면 그대로 섞지 않습니다.
- 원본 payload와 SHA-256, 수집 실행, 품목·계열별 연결을 함께 복원합니다. 지역은 KAMIS 전국 평균이며 소매와 도매의 포장 단위를 유지합니다. 개수↔중량을 임의로 환산하지 않습니다.
- 새 품목은 기존 **v2 앙상블·STRUCT 검증 5품목에 포함되지 않습니다.** 검증 수치·예측·SHAP·구매 권고를 기존 품목에서 복사하지 않습니다. 이 자료는 새 품목의 학습된 예측 결과를 포함하지 않습니다.
- 과거 5개 비교 연도가 충분하지 않은 품목은 평년 판단이 비어 있을 수 있습니다. 도매 선행·배수 등 검증에 이력이 모자라면 기존 서버 정책대로 정보를 제공하지 않습니다.

## 후속 운영

기존 일일 수집 파이프라인은 소매 계열이 있는 품목을 자동으로 선택하므로 새 KAMIS 품목도 수집 대상이 됩니다. 기존 5품목의 v2 검증 범위는 변경하지 않았습니다. 신규 품목의 v5 예측은 기존 파이프라인의 별도 검증 기준을 통과한 경우에만 공개해야 합니다.

지표 배치를 기존 5개 ID만 지정해 실행하고 있었다면, 새 품목 ID에도 `app.indicator_batch`를 실행하도록 담당자가 스케줄을 확장해야 합니다. 이번 자료의 import는 15개 신규 품목 지표를 한 번 생성합니다.

로컬에서 자료를 더 보충할 때(기본 접속은 항상 `DB_*`의 127.0.0.1):

```bash
uv run python -m tools.catalog_expansion recent
uv run python -m tools.catalog_expansion comparison --end YYYY-MM-DD
# 전체 과거 이력이 필요할 때: 날짜별 API라 오래 걸리며 캐시에서 재개 가능
uv run python -m tools.catalog_expansion history --start 2021-10-31 --end 2026-11-27
uv run python -m tools.catalog_expansion indicators
uv run python -m tools.catalog_expansion export
```

기본 날짜는 이번 전달본의 기준일에 고정돼 있습니다. 다음 날 자료를 보충할 때는 `--end`를 명시합니다. `--allow-shared` 없이 공유 주소를 지정하면 도구가 실행을 거부합니다.

## 파일

최종 검증: 신규 15품목·30계열의 실제 관측 **9,983건**, 신규 지표 실행 **15개 SUCCESS**. 14개 신규 품목에 평년 비교가 생성됐으며 대추방울토마토는 과거 비교 연도가 충분하지 않아 평년 판단을 비워 뒀습니다. ID가 1~15인 별도 로컬 스키마에 이관 후 원래 로컬 DB의 품목별 날짜·건수와 일치했고, 두 번 이관해도 품목·별칭·원본·일별 가격 수가 같았습니다. PC·390px 모바일에서 별칭 검색·조건 초기화·분류 조합·주소 상태를 확인했으며, 홈 20개 그래프는 묶음 API 한 번으로 불러왔습니다. 웹 프로덕션 빌드와 로컬/공유 접속 방어 테스트 5개를 통과했습니다.

- `apply_catalog.py`: 기존 WAS 의존성을 사용하는 이관 도구. WAS 루트에서 실행.
- `01_register_items.sql`: 검토 가능한 트랜잭션 SQL. 고정 ID 없음.
- `02_kamis_observations.json.gz`: 신규 품목의 실제 KAMIS 관측 원본. 개인정보·키·DB 접속 정보 없음.
- `catalog.json`: 품종·시장별 단위·검색 별칭·선정 목적.
- `verification.json`: 로컬 최종 검증 결과.
- `SHA256SUMS.txt`: 전달 파일 무결성 확인용.

웹 변경에는 상시 검색창, 이름·별칭 검색, 결과 개수, 분류·판단 필터 조합, 검색 조건 초기화, 홈 그래프의 묶음 요청을 포함합니다. DB 적용과 별도로 수정된 웹 코드를 받아야 합니다.
