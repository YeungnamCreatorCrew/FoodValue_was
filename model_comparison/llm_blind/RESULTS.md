# LLM 블라인드 예측 실험 결과 (2026-11-24)

멘토 제안("트리 모델 튜닝 대신 DB 데이터를 LLM에 프롬프팅해서 예측시켜 보라")을 시험한 결과다.
예측자는 Claude Opus 5.5이며, 대화 안에서 프롬프트를 읽고 직접 판단했다. 코드나 통계 모델은 쓰지 않았다.
절차는 `PROTOCOL.md`에 있다.

## 설정
- 대상: 기준서 v1의 10개 계열(대파·양파·깐마늘·배추·무 × 소매·도매), D+1~D+7 예측
- 기준일: 검증 구간(2024-11~2025-10) 튜닝 목록에서 4주 간격으로 고른 **14개**. 평가 점은 653개(앙상블 실패 5점은 기준서 §8.2대로 naive로 대체). 최종 시험 구간은 쓰지 않았다.
- 입력: 기준일마다 생성한 프롬프트(`eval_prompts/`). 들어간 정보는 다음과 같다.
  - 자기 계열 4주 일별값과 26주 주평균
  - 1~3년 전 같은 시기의 흐름
  - 상대 시장(D−1까지)
  - 전국 기상(D−1까지)
  - 명절 일정
  - KREI 관측 월보 추출값(공개일 ≤ D)
  - 연도는 가렸다.
- 출력: 현재가 대비 % 변화(0 = naive) → 원 단위 가격으로 변환
- 누수 방지: 기준일 k의 예측 파일을 SHA-256으로 잠근 뒤에야 k+1 프롬프트를 만들었다(`lock.log`, 18건). 채점은 14개를 모두 잠근 뒤 한 번만 했다.
- 사전 보정: 2023-11~2024-08의 4개 기준일(dev)로 판단 규칙을 정한 뒤 고정했다. dev 결과는 naive 대비 +5.0%였다.

## 결과 (같은 653점, 기준서 §8 방식 macro MAPE)

| 모델 | macro MAPE | naive 대비 | 계열 승 | 월 블록 부트스트랩 95% (Δ=naive−모델, %p) |
|---|---|---|---|---|
| naive | 3.996% | — | — | — |
| mean7 | 6.235% | −56.0% | 0/10 | [−3.49, −1.08] |
| **LLM (Claude)** | **3.738%** | **+6.46%** | **7/10** | **[+0.04, +0.47]** |
| 앙상블 (XGB+LGBM+ARIMA, ens-val-base-arima) | 3.659% | +8.43% | 8/10 | [+0.13, +0.54] |
| (사후 탐색) LLM·앙상블 단순 평균 | 3.642% | +8.86% | — | 사후에 본 값, 채택 근거 아님 |

- LLM은 naive를 **근소하게** 이겼다(부트스트랩 하한 +0.04%p). 기준일 하나씩 빼도 +4.9~+7.3%.
- **개선의 약 2/3가 배추 소매 한 계열에서 나왔다.** 배추 소매를 빼면 LLM +2.57%, 앙상블 +5.24%로 차이가 두 배가 된다. 배추 소매의 큰 이득은 2024-11-01(12.2→6.4), 2025-08-04(4.7→0.9), 2025-10-27(21.8→15.4)에 몰려 있다.
- 앙상블과의 차이(0.08%p)는 95% 구간 [−0.22, +0.06]으로 구분되지 않는다. 표본이 작아 **같다고 말할 수도 없다**.
- 계열별: 소매 5개는 모두 naive보다 좋음. 도매는 양파·깐마늘만 좋고 대파·배추·무 도매는 naive보다 나쁨.
- 예측 크기: 평균 |예측 변화| 1.0%, 평균 |실제 변화| 4.1%. 26.5%의 점을 0%(naive)로 둠. 방향 적중 58%(움직임을 예측한 점 기준).

## 해석
- 잘 된 것: **도매→소매 전달**과 **같은 시기 계절 흐름(작형 전환 등)**을 근거로 소매를 따라가게 한 부분이다. 판단 보조 지표 검증(도매 2주 상승 뒤 소매 상승)과 같은 방향의 결과다.
- 안 된 것: 도매다. 크게 움직인다고 본 판단(|변화| ≥ 2%) 20건 중 맞은 것도 있다(양파 04-14 하락, 배추 11-01 하락, 대파 03-17 하락). 그러나 10-27 배추·무 도매 하락 판단(과거 3년 모두 하락이었지만 이번엔 상승)과 대파 12-23·01-20 상승 판단이 크게 틀렸다.
- 결론: LLM 프롬프팅은 naive를 근소하게 이겼다. 하지만 그 이득은 배추 소매에 크게 기대고 있고, 앙상블보다 낫다고도 같다고도 말할 수 없다. 아래 오염 가능성까지 고려하면 "LLM이 트리 모델을 대체할 수 있다"는 근거로는 약하다.

## 한계 (결과를 해석할 때 반드시 같이 볼 것)
1. **사전 지식 오염 가능성.** 검증 구간(2024-11~2025-10)은 모델 학습 마감(2026-06) 이전이다. 연도를 가렸지만 실제로 새는 단서가 있다. dev 2024-03-11 프롬프트에는 윤년에만 있는 02-29가 나오고, 휴장일 공백(05-15 부처님오신날, 5월 초 연휴)과 요일+월-일 조합으로도 연도가 정해진다. 솔직히 적으면, dev 2024-08-19를 예측할 때 "2024년 가을 배추 파동"을 떠올렸다(dev라 채점에는 영향이 없다). eval에서는 특정 연도나 사건을 의식적으로 떠올리지 않았다. 다만 개선이 몰린 배추 소매(2024 가을 급등 직후의 하락, 2025 여름)가 바로 기억이 도움이 될 수 있는 구간이라, 무의식적 영향은 배제할 수 없다. 결과가 낙관적일 수 있다. 깨끗하게 확인하려면 모델 학습 이후 기간이 필요한데, 우리 데이터에서는 그것이 최종 시험 구간(2025-11~)뿐이다. 기준서 §7.2에 따라 시도하지 않았다.
2. **표본이 작다.** 기준일 14개뿐이다. LightGBM 튜닝 때도 기준일 표본 노이즈가 설정 차이보다 컸다.
3. **재현성이 없다.** 예측자가 대화 속 Claude 자신이다. 같은 프롬프트를 API로 다시 돌리면 값이 달라질 수 있다. 프롬프트 파일은 남아 있으므로 API(Gemini 등)로 같은 실험을 다시 할 수는 있다.
4. **운영 비용이 크다.** 기준일 하나에 프롬프트가 약 1.7만 자(10개 계열)다. 매일 돌리면 무료 플랜 한도에 걸린다.
5. KREI 추출값은 `historical_version_status=unverified`이고, 일부 기간(12~2월)은 보고서가 비어 최신값이 오래됐다.
6. dev 4개 기준일과 eval 14개 모두 같은 사람(Claude)이 판단했다. dev에서 결과를 본 뒤 규칙을 만들었지만, eval에서는 규칙을 고친 적이 없다.

## 파일
- `make_prompt.py`: 프롬프트 생성(누수 방지 규칙 포함)
- `protocol.py`: 기준일 목록·잠금·다음 프롬프트 생성
- `score.py`: 채점
- `origins.json`, `PROTOCOL.md`, `lock.log`, `preds/`, `dev_prompts/`, `eval_prompts/`: 절차·잠금 기록·예측·프롬프트
- `result_eval_s1.0.json`, `points_eval_s1.0.csv`: 채점 결과·평가 점

## 직접 돌려 보기
- 필요한 데이터(Git에 없음, 팀 공유 드라이브): `data/snapshots/fv-snap-20261031-v1/`, `data/snapshots/FoodValue_KREI_Snapshot_20261118_r2/`
- 프롬프트 재생성: `uv run python -m model_comparison.llm_blind.make_prompt 2024-11-01 --out /tmp/prompts`
  - `eval_prompts/2024-11-01.md`와 같아야 한다.
  - 다른 LLM(Gemini 등)에게 이 프롬프트를 넣고, 같은 형식(`series_id,h1..h7`, 현재가 대비 %)으로 답을 받아 비교할 수 있다.
- 채점: `uv run --extra prices python -m model_comparison.llm_blind.score eval`
  - 잠금 해시(`lock.log`)와 `preds/eval/`이 맞아야 실행된다.
  - 앙상블 비교 행은 `experiments_v2/`(Git에 없음)가 있을 때만 나온다.
- 후속으로 만든 구조적 모델(같은 가설을 식으로 옮긴 것)은 `model_comparison/structural/README.md`에 있다.
