# v2 첫 결과 (2026-11-12, 클라우드 작업 환경, v1 스냅샷 + v2 추가 자료)

모두 XGBoost. "통합" = 10계열 통합 학습(`run_pooled`), "계열별" = v1 실행기(`run_backtest`, `config_p1.json` params).
> 이 문서의 숫자는 **원본 추출본 `fv-v2-extra-20261031`**(반입량 오입력 5건 포함)으로 냈다. 2026-11-16부터 실험 기본 입력은

## 6. Ridge v2를 앙상블 구성원으로 (2026-11-19, Windows PC, 튜닝 목록 53개 기준일)

Ridge v2(`model_comparison/ridge/v2/`, PR #49)는 별도 실행기로 돌리지만 예측 형식(`predictions.csv` 14열)과
`config.json`의 `origin_list`가 같아 `ensemble.py`로 바로 합칠 수 있다. 비교 기준은 §3의 두 구성원을 같은 PC에서 다시 돌린 결과다
(XGBoost 4.326%, LightGBM 4.340%, 앙상블 4.285% — §3과 같은 값). AutoARIMA p2 예측은 검증 기준일만 있어 이 비교에는 넣지 않았다.

| Ridge 설정 (alpha 10) | Ridge 단독 | 기준 + Ridge 10% | 기준 + Ridge 20% |
| --- | --- | --- | --- |
| 기준: XGBoost(Huber + inv_scale) + LightGBM | — | 4.2847% | 4.2847% |
| `no_ow` (모든 자료 − 주산지 날씨, 58개) | 4.597% | **4.2780%** | 4.2799% |
| MARKET + 계열 구분 | 4.501% | 4.2818% | 4.2841% |
| `v1feat` (MARKET + 전국 기상 + 명절) | 4.539% | 4.2852% | 4.2896% |
| CONTROL (가격 이력 + 계열 구분) | 4.606% | 4.2872% | 4.2952% |

- 같은 비중(1/3)으로 넣으면 나빠진다: MARKET 4.296%, `v1feat` 4.306%. Ridge 단독(4.50%)이 두 트리 모델(4.33%)보다 약하기 때문이다.
- Ridge alpha(1·100·1,000·10,000, MARKET 기준)는 단독·앙상블 모두 차이가 0.01%p 안쪽이라 결과를 바꾸지 않는다.
- 단독 성적과 앙상블 기여가 다르다: Ridge 단독으로는 `no_ow`가 가장 약한 편인데 앙상블에는 가장 도움이 된다.
  트리 모델(35개)과 다른 특징(반입량·다른 품목 가격·환율·생산량 포함 58개)을 써서 틀리는 방식이 달라진 것으로 보인다.
- Ridge가 보완하는 계열: 배추 도매(9002)·무 소매(9011). 무 도매(9012)·대파 도매(2)·양파 도매(7)는 나빠진다(MARKET 1/3 기준).
- **판단:** 가장 좋은 `no_ow` 10%도 기준보다 0.007%p로, §1의 시드 흔들림(약 ±0.01%p)보다 작다. 여러 후보 중 고른 값이라
  튜닝 목록만으로는 효과가 있다고 말할 수 없다. Ridge `no_ow` 10%를 후보로 두고, 구성원 확정 때 검증 기준일(AutoARIMA 포함)로 한 번 확인한다.
- 기록: Ridge 실행은 `model_comparison/ridge/v2/EXPERIMENT_LOG.md`·`RESULTS.md`, 앙상블은 `experiments_v2/ens-robust-lgbm-ridge-*-tune-20261118-01`(커밋하지 않음).

## 7. LightGBM 구성원 튜닝 (2026-11-19, macOS arm64, LightGBM 담당)

기준 XGBoost(`v1feat_xgb_robust`, seed 42)는 고정하고 LightGBM만 바꿔, **XGBoost와의 같은 비중 앙상블**로 판단했다.
튜닝 목록 53개(naive 4.607%)에서 고르고 검증 244개(naive 4.913%)는 마지막 한 번만 확인. 시도 15회(예산 40회),
기록 `model_comparison/v2/lgbm_tune/tuning_log.csv`·`seed_check.csv`, 설정 `configs/lgbm_tune/`.

### 검증 전체 244개 기준일 (seed 42, 한 번만 확인)

| 설정 | MAPE | naive 대비 | 승 | 관문 |

| LightGBM 기본값 | 4.660% | +5.15% | 9/10 | 5 미달 |

| 앙상블: XGBoost + LightGBM 조합 | 4.609% | +6.18% | 9/10 | 모두 통과 |
| **앙상블: XGBoost + LightGBM 기본값 + AutoARIMA p2** | **4.595%** | **+6.47%** | 9/10 | 모두 통과 |
| 앙상블: XGBoost + LightGBM 조합 + AutoARIMA p2 | 4.604% | +6.29% | 9/10 | 모두 통과 |

- **판단: 조합은 채택하지 않는다. LightGBM 구성원은 기본값(`v1feat_lgbm`) 유지.** 검증에서는 단독 0.046%p 나쁘고, 앙상블은 동률(ARIMA 없음) 또는 0.009%p 나쁘다(ARIMA 포함).
- 검증을 한 번 봤으므로 LightGBM 튜닝은 여기서 멈춘다(남은 예산 25회를 쓰면 검증으로 고르는 것이 됨).
- 재현: 기본 앙상블 4.606%·ARIMA 포함 4.595%로 §3·§5의 4.603%·4.592%와 기기 차이 범위에서 같다.
- **주의(팀 판단 기준 관련):** 튜닝 목록은 검증 244개 중 약 52개다. 조합은 튜닝 목록에서 세 시드 모두 0.03%p 좋았지만
  나머지 약 190개 기준일에서 그 이득이 사라졌다. 시드 반복은 모델 무작위성만 재고 기준일 표본 흔들림은 재지 못하며,
  후자가 더 크다(앙상블 Δ 95% CI 폭 약 0.35~0.45%p). 튜닝 목록에서 0.01~0.03%p 수준의 앙상블 개선은 그것만으로 효과라고 보기 어렵다.
- 결과 폴더(커밋하지 않음): `experiments_v2/*-tune-20261119-*`, `v1feat_xgb_robust-validation-20261119-01`, `v1feat_lgbm-validation-20261119-01`,
  `lgbm_et_hl365-validation-20261119-01`, `ens-val-{base,base-arima,new,new-arima}-validation-20261119-01`.

## 9. AutoARIMA 구성원 튜닝 (2026-11-19, Windows PC, AutoARIMA 담당)

XGBoost 튜닝판(`v1feat_xgb_tuned`)·LightGBM 기본값(`v1feat_lgbm`)은 고정하고 AutoARIMA만 바꿔, **세 모델 같은 비중 앙상블**로 판단했다.
AutoARIMA는 v1 실행기(`tools.run_backtest --phase focus --origins tune`)로 돌리고 `ensemble.py`로 합쳤다. 튜닝 목록은 검증의 일부지만
AutoARIMA는 기준일 목록에 따라 재학습 날짜가 달라지므로 검증 예측에서 골라내지 않고 튜닝 목록으로 직접 돌렸다.
시도 6회(예산 40회), 기록 `model_comparison/autoarima/v2_tune/`(`tuning_log.csv`, 설정 6개).

## 결론(현재까지)

1. **추가 자료(가락 반입량·주산지 날씨·다른 품목 가격)는 7일 뒤 전국 평균 가격 예측을 개선하지 못했다.** 넣을수록 나빠지는 경우가 많다.
2. **통합 학습은 계열별 학습과 비슷하거나 조금 낫다.** 튜닝 목록에서는 계열별이 0.02%p 낫고, 검증 전체에서는 통합이 0.06%p 낫다 → 큰 차이는 아님.
3. 성능을 끌어올린 자료는 지금까지 **상대 시장 가격(MARKET)** 하나다.
4. 학습 방식에서는 **Huber 손실 + 계열 변동 크기 가중**과 **성격이 다른 두 모델 앙상블**이 효과가 있었다(§3).
   새 자료도 이 두 구성원 + 앙상블로 비교하는 것을 권장한다 — 자료 효과가 작아(±0.02%p) 단일 모델 잡음에 묻히기 쉽다.
5. KREI 관측월보는 r2(평년 대비 제외)로 다시 봐도 앙상블을 4.603 → 4.647%로 나쁘게 했다(§4). 채택하지 않는다.
6. Ridge v2는 앙상블에 10%로 넣으면 튜닝 목록에서 최대 0.007%p(`no_ow`) 좋아지지만 잡음 수준이다(§6). 검증 확인 전까지 구성원 후보로만 둔다.
7. LightGBM 구성원은 15회 튜닝 중 튜닝 목록 최고 조합(`extra_trees` + 반감 365일)이 검증에서 개선을 잇지 못해 기본값을 유지한다(§7).
8. XGBoost 구성원은 21회 튜닝으로 `combo`(트리 600·깊이 6·mcw 5·Huber 0.03)를 골랐다. 튜닝 목록 개선은 잡음 수준(−0.007%p)이지만 검증에서는 3종 앙상블 4.592% → **4.561%**(naive 대비 +7.15%)로 좋아졌다(§8). 시드 확인 뒤 구성원 후보로 올린다.
   튜닝 목록에서의 작은 앙상블 개선(0.01~0.03%p)은 검증으로 옮겨지지 않을 수 있다.
9. AutoARIMA 구성원은 6회 튜닝 중 튜닝 목록 최고(p1, 명절 없음)가 검증에서 p2와 같아(4.5612 vs 4.5614%) p2를 유지한다(§9).
   학습 창 단축·level 변환은 앙상블을 나쁘게 한다.
