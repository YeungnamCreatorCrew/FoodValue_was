# KREI 월보 공개 시점·과거 버전 검증 및 Ridge v2 사용 가능성 진단

작성일: 2026-11-18 KST / 기록 시각은 각 증거의 timezone-aware ISO 값 참조. 브랜치: `feat/ridge-v2`.

**STRICT는 Tune 기준일에 1개 PDF의 1개 연관 전망 묶음, 3개 수치지표만 조건을 통과했다. EXPLORATORY는 12개 PDF의 24개 연관 전망 묶음, 54개 수치지표를 연구용으로 연결했다.** 기존 V1/V2 승인 기록 0건은 변경하지 않았다. 새 STRICT 사용 가능성 판정과 최종 모델 채택 승인은 다르며, 모델 채택 승인·학습 실행은 모두 0건이다.

정식 결과 디렉터리: [publication_verification/runs/publication_20261117T162601173971Z](publication_verification/runs/publication_20261117T162601173971Z/). 최종 진단은 `diagnostics_v3/`, 최종 PDF 등급은 `archive_adjudication/pdf_evidence_grades.csv`이다. `diagnostics/`, `diagnostics_v2/`와 실행 루트의 초기 등급 파일은 조사 중간 결과로 보존했으며 이 보고서의 최종 수치에 혼합하지 않았다.

## 1. 입력 확인과 보존

`REPORT.ko.md`, `VERIFICATION_V2_REPORT.ko.md`, `verification_v2/README.ko.md`, `results_20261117T140214398412Z/`, `research_evidence.json`, 검증 코드 및 기존 `asof.py`를 직접 확인했다. 요청에 쓰인 중첩 경로 `verification_v2/verification_v2`는 없으며 실제 코드는 `verification_v2/` 바로 아래에 있다. 기존 경로 `data/krei_monthly`는 없고 이동된 현재 위치의 원본·코드·감사 기록이 존재한다. 파일 이동·삭제·이전 경로 복원은 하지 않았다.

기존 120 PDF / V1 후보 1,934건 / V2 근거 1,050건 / 수치 검증 428건 / PDF 표기 날짜 확인 119개 / 과거 버전 증명 0건 / 학습 승인 0건이라는 **이전 실행 결과는 그대로 보존**했다. 이번에는 공개 증거와 버전 증거를 새로 추가했으며 OCR 재실행이나 기존 숫자 수정은 하지 않았다.

무결성: 보호 대상 기존 파일 **7,792개**를 시작·종료 SHA-256으로 비교했다. 변경·누락 **0개**, 새 작업 영역 밖 추가 **0개**. 원본 PDF **120/120** 해시 일치, 이전 배포 봉인 **28/28** 일치. 기존 `asof.py`, Ridge p1/p2/v2, 실험 결과 및 스냅샷을 수정하지 않았다. 상세는 `preservation_before.json`, `preservation_after.json`, `diagnostics_v3/audit_summary.json` 참조.

## 2. 공식 공개 기록 조사

우선 [KREI 공식 월보 목록](https://aglook.krei.re.kr/main/uObserveMonth/OVR0000000036?queryType=2025), [엽근채소 목록](https://aglook.krei.re.kr/main/uObserveMonth/OVR0000000008?queryType=2025), [공식 XML API](https://aglook.krei.re.kr/main/api/montlyReport?yyyy=2025&ovr_item_code=OVR0000000036), [공식 월별 레코드](https://aglook.krei.re.kr/main/uObserveMonth/OVR0000000036/monthList?queryType=2025)를 읽었다. 2020~2025년 두 묶음의 목록 12건, 연도별 XML 12건, 월별 레코드 JSON 12건에서 기존 120개를 대조했다. 모두 HTTP 200으로 접근됐다. 연도별 XML은 `yyyy`, `ovr_item_code`만 주면 해당 연도의 10개 발행 월을 반환했다.

API `reg_date`·`mod_date`, UI `isrt_DT`·`updt_DT`, 선언 발행일 `pub_YYYYMMDD`, 첨부파일 식별자·크기를 별도로 보관했다. UI 내부 `id`와 다운로드용 `org_ID`는 다르다. 현재 API 메타데이터는 이전 수집본과 120개 모두 같았고 현재 첨부 크기도 120개 모두 로컬과 같았다. **현재 메타데이터의 일치나 빈 수정일은 과거 파일이 교체되지 않았다는 증거가 아니다.** 현재 공식 데이터에 과거 전체 파일 해시나 불변 버전 이력은 확인하지 못했다.

[공식 2021 공표 일정](https://aglook.krei.re.kr/main/board/1/1/read/682)은 예정 일정이다. 화면의 다음 호 예정일이나 인포그래픽·별도 전망 요약본을 해당 월보의 실제 게시일로 바꾸지 않았다. 조사한 공식 경로에서 대상 PDF와 연결되는 완전한 개정·교체·정오표 이력을 확보하지 못했다. 기록이 없다는 사실을 무수정 증명으로 해석하지 않았다.

공식 경로 조사 후 공개 Wayback CDX에서 대상 다운로드 주소와 일치하는 20건을 찾았다. 이들은 `application/octet-stream`으로 분류되어 있었다. 20개 PDF 응답과 공식 페이지 HTML 8개를 새 실행 영역에만 보존했다. 기존 120개 원본을 공식 사이트에서 다시 다운로드하거나 덮어쓰지 않았다. 별도 정적 첨부 경로의 모든 MIME 검색도 수행했으나 현재 120개 PDF의 정적 URL과 맞는 보존본은 찾지 못했다. 이는 모든 아카이브의 부재를 증명하지 않는다.

## 3. 공개 시점 A와 내용 동일성 B

A는 당시 공식 사이트에 해당 월보가 공개적으로 나열되었거나 PDF가 응답되었다는 관측이다. B는 그 시점의 완전한 PDF가 현재 로컬 파일과 동일하다는 검증이다. 둘을 독립 필드로 저장했다.

- PDF 인쇄 날짜: 문서 자체의 발행일 표기이다.
- API/UI 등록·수정 날짜: 현재 서버가 제공하는 등록 정보이다.
- `website_publication_known_by`: 보존된 공식 페이지·PDF를 실제 관측한 시각. **그때까지는 공개되었다는 상한이며 최초 게시 시각이 아니다.**
- `historical_content_verified_by`: 현재 파일과 전체 해시가 일치하는 완전 보존본의 가장 이른 수집 시각. 앞선 목록이나 부분 보존 시각으로 소급하지 않는다.
- `website_first_publication_at`: 120개 모두 미확인(null)으로 유지했다.

아카이브 응답 SHA-1을 CDX digest와 대조한 뒤, 완전 보존 PDF는 원본 SHA-256과 비교했다. URL만 같거나 파일 앞부분만 같으면 B를 통과시키지 않았다. 과거 PDF 응답 20건은 **전체 일치 6건, 일부만 일치 11건, 일부 바이트 차이 확인 2건, CDX digest 불일치로 사용 제외 1건**이다. 부분본은 주로 1MiB에서 잘렸고 `warning: ... truncated ... length`가 있었다. digest가 다른 재생 응답은 요청한 과거 수집본으로 신뢰하지 않았다.

새 등급은 다음과 같다. PDF별 근거 URL·확인 시각·증거 종류·판단 이유·불확실성은 `archive_adjudication/pdf_evidence_grades.json/csv`, 원시 증거는 `network/`에 있다.

| 새 증거 등급 | PDF 수 | 해석 |
| --- | --- | --- |
| VERIFIED_VINTAGE | 6 | 과거 완전 PDF와 현재 원본의 전체 SHA-256 일치 |
| VERIFIED_PUBLICATION | 45 | 과거 공식 공개 기록 확인, 전체 파일 동일성 미확인 |
| RESEARCH_CANDIDATE | 69 | 현재 공식 메타데이터·인쇄 날짜 등 간접 근거 |
| UNVERIFIED | 0 | 근거 부족 |

따라서 공개 관측 A는 **51/120**, 전체 내용 동일성 B는 **6/120**, 정확한 최초 홈페이지 게시 시각은 **0/120**이다. `RESEARCH_CANDIDATE` 69개는 검증 완료 데이터가 아니다. 등급 자체를 학습 승인으로 사용하지 않았다.

## 5. STRICT / EXPLORATORY 계약

STRICT는 기존 `asof.py`를 **수정 없이 호출**한다. 수치·품목·대상 기간·단위가 검증되고, `VERIFIED_VINTAGE`, 과거 공개 관측, 전체 파일 동일성이 모두 있어야 한다. 그 위에 완전 동일본 관측 시각과 공개 관측 시각이 실제 cutoff 이전인지 추가 차단한다. 기존 날짜 종료 경계·등록/수정 시각 차단도 유지한다. 어댑터의 `verified_as_published`는 이 추가 시각 차단 뒤에만 전달하며, ‘최초 발행본 동일성’으로 의미를 넓히지 않는다. 입증한 과거 수집 시점부터 사용할 수 있다는 뜻이다.

EXPLORATORY는 별도 `policies.py`와 별도 스냅샷이다. 검증된 인쇄 날짜, 공식 선언 날짜, 원래/현재 API 및 UI 등록·수정 시각의 최댓값을 간접 날짜 경계로 삼고 기본 **7일 지연**한다. 인쇄 날짜는 해당 날짜가 끝난 KST 경계를 사용한다. raw 등록 시각의 KST 해석은 가정으로 명시했다. 보존본 수집 시각은 최초 게시 시각의 하한이 아니므로 이 간접 날짜 경계에 무조건 대입하지 않았다. 실제 공개가 cutoff 전에 관측되었는지는 별도로 표시한다. **7일·30일 지연은 파일 버전 불확실성을 해결하지 않는다.**

월/월 범위는 기간이 종료되지 않고 시작 월이 3개월 이내인 후보만 연결했다. 연도/연산 표기는 같은 명목 연도 또는 다음 명목 연도만 연결했고, 작형별 실제 수확 시작·종료일이나 남은 일수는 만들지 않았다. 연간 값은 연간 추정·전망 정보이며 월별 미래 전망이라고 주장하지 않는다. 기본 진단에는 임의의 62일 신선도 상한을 두지 않았고, 오래된 연간 전망 유지에 따른 영향을 별도 계산했다.

두 정책 모두 동일한 대상·품종·작형·가공·시장·등급·단위·비교 기준·지역 언급·면적 의향 정의 안에서만 중복을 제거한다. 동일 조건의 최신 호가 충돌하면 오래된 값으로 몰래 대체하지 않는다. 숫자 결측을 0·평균으로 채우지 않고 구간 중간값도 만들지 않는다. 정책 승인 여부, 증거 등급, 최종 모델 채택 여부는 분리했다.

## 6. 수치 중복과 실제 Tune 연결

기존 검증 428행을 재검증 완료 행으로 그대로 유지했다. 그중 같은 의미 범위의 문장·표 중복을 묶으면 363개 수치지표 묶음이며 중복 근거는 65행이다. **33묶음/67근거행에 서로 다른 값이 있어 사용을 보류**했다. 반올림 차이와 실제 충돌을 자동으로 구별하거나 평균내지 않았다. 남은 것은 **330개 수치지표 이벤트**, 발행 호 간 같은 수치 상태를 다시 합산하지 않은 고유 상태는 **273개**이다.

생산량 수준·전년 대비·평년 대비는 같은 전망을 설명하는 서로 관련된 지표일 수 있다. 이들 숫자나 단위를 통합하지 않고 별도의 `related_outlook_cluster_id` 관계만 붙였다. 따라서 ‘지표 수’도 통계적으로 독립적인 전망 표본 수를 뜻하지 않는다.

읽기 전용 입력은 `data/snapshots/fv-snap-20261031-v1/origins_tune.csv`와 `price_series.csv`이다. Tune 기준일 **2024-11-01~2025-10-27, 53개**, 가격 계열 **10개**를 확인했다. 날짜만 있는 기준일은 보수적으로 KST 00:00으로 진단했다. 가격 관측값·정답·예측 결과를 사용하거나 모델을 학습하지 않았다.

## 9. KREI_OUTLOOK 특징 준비

`diagnostics_v3/STRICT/numeric_features_long.csv`와 `EXPLORATORY/numeric_features_long.csv`에 서로 다른 스냅샷을 생성했다. 원문 문장·페이지·PDF 경로/URL·SHA-256·원래 fact ID·지표 범위·근거 등급·시점 가정이 함께 있다. 기존 Ridge 설정에는 연결하지 않았다.

- 생산량 수준 및 전년/평년 대비율: STRICT는 위 양파 1묶음만 가능하다. 탐색 정책에서는 추가 후보가 있다.
- 재배면적 수준/변화율·출하량 변화율: 이번 Tune에서 EXPLORATORY 후보만 있다. 면적 ‘의향’과 추정 면적은 구분한다.
- 가격 전망 수준/변화율: 전체 2020~2025 원자료에는 후보가 있으나 이번 53개 Tune 기준일에 선택 가능한 수치 가격 전망은 **두 정책 모두 0개**이다. 존재 플래그로 숫자를 만들지 않았다.
- 전년·평년 비교 기준을 별도 필드로 유지하고 감소는 음수로 보존했다. 퍼센트포인트 수정폭과 원래 단위 수정폭을 구분했다.
- 경과 기간: STRICT는 확인된 공개 관측 이후 기간, 탐색은 간접 날짜 경계 이후 기간으로 다른 필드를 썼다. 실제 최초 발표 이후 경과일로 단정하지 않았다.
- 대상 월/범위와 cutoff 관계: 실제 월 표기가 있는 경우에만 일·월 관계를 계산한다. 연산의 달력 일수는 null이다.
- 전망 수정폭: 같은 대상·범위·단위·비교 기준의 이전 적격 호가 있을 때만 계산했다. STRICT 0쌍, EXPLORATORY 31개 지표 쌍이다. 반복된 850개 계열×기준일 행을 850개 독립 수정 사례로 세지 않는다. 탐색 수정폭에도 버전 불확실성이 남는다.
- 사용 가능 여부·확인 상태는 메타데이터 특징이다. 수치 전망과 별도이며 결측 숫자를 0으로 바꾸지 않았다.

## 10. 민감도·실패·보류 사유

탐색 날짜 지연만 바꾼 결과는 다음과 같다. 기간 종료·동일 범위 최신 호·충돌 차단은 유지했다.

| 탐색 지연 | 수치 있는 셀/530 | 결측률 | 선택 지표 |
| --- | --- | --- | --- |
| 0일 | 280 | 47.17% | 54 |
| 7일 | 274 | 48.30% | 54 |
| 30일 | 258 | 51.32% | 51 |

주요 병목은 **Tune 이전의 완전한 과거 파일 증거 부족**과 **2024~2025년 해당 대상 기간의 수치 검증 데이터 희소성**이다. 추가로 33개 동일 범위 값 충돌, 대상 기간이 지난 정보, 월별 수확 경계 미확인, 한 PDF의 날짜 충돌이 있다. 428건을 통과시키기 위해 검증 조건을 완화하지 않았다.

초기 sandbox 요청은 로컬 소켓 접근 거부(WinError 10013)였고 승인된 네트워크 접근으로 재시도해 공식 경로는 성공했다. 이를 KREI 서버 장애로 보고하지 않았다. Wayback available API의 HTTP 200 안에 포함된 timeout 오류는 ‘보존본 없음’으로 해석하지 않았다. 선택한 Common Crawl 인덱스 조회의 HTTP 404도 전체 아카이브 부재 증명으로 쓰지 않았다. PDF 재생 1건은 CDX digest가 달라 증거 사용을 제외했다. 요청은 1.2초 간격, 20초 timeout, 최대 2회, 최대 80MiB이며 유료 API·비밀키·기관 문의는 사용하지 않았다.

초기 경로 지정 오류로 별도 `runs/publication_20261118T000000Z/`에 남은 5건의 실패 네트워크 probe는 삭제·이동하지 않았으며 이 실행의 성공 집계에 사용하지 않았다. canonical 실행은 본문 맨 위의 디렉터리다.

## 11. 다음 단계와 최종 판단

우선 `diagnostics_v3/priority_evidence_review_queue.csv`를 검토한다. 우선순위 0은 바이트 차이가 보인 2024년 4·5월 양념채소이며 완전 과거본과 내용 비교가 필요하다. 우선순위 1은 탐색 스냅샷에 실제 선택되었으나 vintage가 검증되지 않은 PDF이다. 전체 미해결 자료는 PDF별 큐에 남겼다. 현재 파일의 향후 수정 여부를 알 수 있도록 앞으로는 공식 공개 페이지·응답·원본 파일을 수집 시점별 append-only 저장하고 SHA-256 및 최초 관측 시각을 봉인하는 방식이 필요하다. 이 작업만으로 이미 지나간 최초 공개 이력을 복원할 수는 없다.

DB 적재는 이번 범위에서 실행하지 않았다. 향후에는 문서, 공개 관측, 보존 버전/해시, 수치 fact, 정책별 시점 판정, 특징 스냅샷을 별도 테이블/관계로 설계해야 한다. 기존 fact를 덮어쓰는 UPDATE 대신 새 버전과 출처 관계를 기록하고, STRICT 판정과 탐색 가정을 분리하는 설계가 적절하다.

**1. 지금 Ridge v2 Tune에 사용할 수 있는가?** 제한적으로 가능하다. 새 STRICT 시점·내용 계약을 통과한 것은 과거 연간 양파 전망 1묶음의 3개 지표뿐이다. 10개 계열 전체의 신뢰할 수 있는 월보 특징군으로 바로 적용하기에는 부족하다. 기존 승인 0건을 소급 수정하지 않았으며 실제 학습·최종 채택은 하지 않았다.

**2. 정책별 얼마나 가능한가?** STRICT 출처 적격은 PDF 6개·검증 근거 58행·충돌 제외 42지표이나, 실제 Tune 대상 기간·시점을 통과한 것은 PDF 1개·3근거행·3지표·전망 1묶음이다. EXPLORATORY 출처 후보는 PDF 119개·검증 근거 428행·충돌 제외 330지표이며, 실제 Tune 스냅샷은 PDF 12개·56근거행·54지표·전망 24묶음이다. 탐색 자료는 STRICT 학습 승인 데이터가 아니다.

**3. 가장 큰 병목은 무엇인가?** 현재 PDF와 동일한 완전 과거본을 적절한 cutoff 이전에 확보하는 것이다. 날짜만 늦추거나 API 등록일을 신뢰하는 방식으로 해결되지 않는다. 수치 검증 후에도 최신 대상 기간의 품목별 데이터가 적다는 문제가 남는다.

**4. 시장·날씨·생산량 변수와 결합하는 단계로 넘어가도 되는가?** 독립된 연구용 결합 설계·결측 진단은 가능하지만, 기존 정식 Tune 및 최종 모델 선정에 자동 결합할 단계는 아니다. STRICT 자료 확대 또는 탐색의 한계를 명시한 별도 실험 계획이 먼저 필요하다. 이번 작업은 공개 증거와 사전 진단에서 종료했으며 Tune/Validation/Test 학습, DB 변경, Git Commit/Push/PR/Merge는 실행하지 않았다.

검증: 정책 회귀 테스트 **10/10 통과**, 실제 특징 스냅샷 **1,514행**의 원본 숫자·출처·시점·품목·충돌 계약 대조에서 위반 **0건**. 재현 코드와 모든 실패 증거는 새 작업 디렉터리에만 저장했다.
