## 4. 문단·표·OCR 개선 내용

네이티브 페이지는 원본 PDF에서 텍스트 블록·글자 크기·좌표를 다시 읽었다. 문단의 주어·콜론 지표를 인과 설명에 등장한 다른 지표와 구분하고, 근처의 관련 제목에서만 품목·기간 근거를 연결했다. 상단 배너에 수입·생산·가격이 함께 있는 경우 각각의 제목을 분리했다. 제목의 증가 방향과 본문의 감소 방향이 충돌하면 검토 대상으로 유지한다.

표는 행·열·셀 좌표를 보존해 검출했다. 검출된 표 전체를 무조건 수치화하지 않고, 연도가 명시된 전망/추정 제목·명시적 지표 열·단위·현재 연산 행·증감률 구역이 분명한 표만 확정한다. **평년의 절대량 행을 평년 증감률로 읽지 않는다.** 전년과 평년 변화율은 직접 쓰인 부호를 보존하며, 절대량에서 새 변화율을 계산하지 않았다. V2에는 표 근거 **143행**, 그중 자동 **137행**이 포함된다. 그래프의 픽셀이나 불명확한 축에서 새 수치를 추정하지 않았다.

네이티브 표 시각 점검 예시는 2024년 5월 조생종양파 3페이지의 **197,014톤**, 2024년 7월 마늘 5페이지의 **284,514톤**이다. 실제 행·열 제목과 단위를 원본 렌더로 대조했다. 본문의 반올림 수치와 표의 정확한 수치를 합치거나 임의 대체하지 않았다.

단위가 양 끝에 반복되는 **‘1,400원∼1,500원’은 하한 1,400·상한 1,500의 범위**로 보존한다. 첫 값만 단일 전망으로 저장하는 오류를 수정했고, 평균 1,450을 생성하지 않았다. 서로 다른 단위나 이해하지 못하는 반복 분모 형식은 검토로 남긴다.

이미지·혼합 PDF는 이전에 로컬 한국어 Windows.Media.Ocr로 얻은 페이지별 캐시를 읽었고, 오류 페이지 2개 영역을 로컬에서 확대 재인식했다. 2020년 8월 엽근채소 3페이지 본문과 표에서 다음을 대조했다.

- `7 30/0` → 원문 **7.3%**, `6.50/0` → **6.5%**, `0.90/0` → **0.9%**: 명확히 본 글자만 교정 이력으로 기록했다. 마지막 단수 수치는 요청한 특징 지표로 새로 내보내지 않았다.

공식 [2021년 공표 일정](https://aglook.krei.re.kr/main/board/1/1/read/682)은 예정 주기를 설명하는 자료이며 실제 파일 버전 증명이 아니다. 공식 [월보 API 설명](https://aglook.krei.re.kr/main/board/2/2/read/1276)은 XML의 PDF 링크 제공을 설명한다. 보존한 연동 명세와 응답에는 등록·수정 필드는 있으나 최초 공개 파일 해시·버전 이력의 보증은 없다. **빈 mod_date를 무수정 증거로 삼지 않았다.**

이는 확인한 공식 자료 범위에서 증거를 확보하지 못했다는 결론이며 모든 외부 아카이브가 없다는 주장도 아니다. 일부 공식 목록·공지 조회는 웹 도구에서 접근 실패 또는 timeout이었고, 원격 DNS·TLS·HTTP 장애라고 확정하지 않았다. 성공한 공식 목록 경로와 실패 경로, 한계는 `research_evidence.json`에 남겼다. 기존 PDF 120개는 네트워크로 다시 요청하지 않았고 기관에 메시지를 보내지 않았다.

모든 수치의 `vintage_status=unverified`를 유지했다. 기존 `asof.py`는 수정하지 않았고, 동일 함수를 통해 미확인 버전·미래 발표·이후 수정본을 차단한다. 날짜만 알려진 발행의 당일 사용도 보수적으로 막는다. 이 경계는 발표 시각을 꾸며 저장하는 값이 아니다.

## 7. KREI_OUTLOOK 특징 준비와 결측률

`KREI_OUTLOOK`은 새 제안 이름이다. 기존 특징 코드·실험 설정에는 연결하지 않았다. `feature_plan.json`의 후보는 출하·생산·재배면적의 전년/평년 변화율, 가격 수준·변화율, 발표 후 경과 일수, 전망 기간까지 남은 기간, 같은 대상 기간의 이전 호 대비 수정폭, 자료·검증 상태다.

- 수치 검증을 거친 428행은 후속 검토의 후보 근거로 활용할 수 있다. 단위·기간·품종·작형·가공형태·시장·등급이 다른 값은 합치지 않는다.
- 범위 수치의 중앙값을 생성하지 않는다. 가격 수준 특징은 명시적 단일 값 또는 별도 하한·상한 설계가 필요하다.
- 경과 일수는 확인된 공개 경계가 필요하다. 연산만 아는 전망에는 대상 날짜까지의 일수를 생성하지 않는다.
- 수정폭은 같은 기간·지표·범위·단위인 두 발행호가 모두 승인된 경우에만 계산한다. 본문의 반올림 값과 표 값을 비교해 가짜 수정폭을 만들면 안 된다.

현재 실제 학습 승인 근거가 **0개**이므로 수치형 학습 특징의 예상 결측률은 **10개 계열 모두 100%**다. 원래 Tune 예측 기준일 53개를 **날짜만 읽어** 10개 계열과의 진단 격자 530개를 확인했으며 학습·평가를 실행하지 않았다. `feature_missingness.csv`는 특징·계열별 지원 근거 수와 차단 사유만 저장한다. 자료 상태 메타데이터 자체는 존재하나 승인된 숫자의 대체값으로 쓰지 않는다. 원본 달력상 1~2월 빈 응답 비중과 학습 승인 결측률도 서로 다른 지표다.

**실제 특징 행렬을 생성하지 않았다.** 임의의 0·평균·가짜 예측으로 학습 가능한 모양을 만들지 않았고, 빈 승인을 숫자 데이터로 포장하지 않았다. 특징 설계·결측 진단·검토 큐만 준비했다.

## 9. 검증 검사와 다음 단계

검증 전용 테스트 **14개 통과**: +9/-9, 전년/평년 각각·공통 방향, 범위 보존, 반복 단위 범위, 혼합 단위 거부, 과거 가격 괄호 제외, OCR `%` 오류 미보정, 기간 미확인 보류, 인과 설명의 지표 혼동, 표의 평년 절대량/증감률 분리, 이동 경로, 기존 as-of 차단을 검사했다. 최종 1,050개 근거와 1,934개 이전 ID에 대해 원문 경로·범위형 값·명시적 표 셀·검증 상태·OCR 신뢰도 NULL·학습 차단 계약을 확인했으며 위반 **0건**이다.

기존 파일 보존 검사 결과는 앞서 제시한 6,940/6,940개 동일 해시다. 기존 보고서·감사 봉인·Ridge p1/p2/v2·스냅샷·실험 기록의 수정·삭제는 없었다. Git reset/clean/commit/push/PR/merge, DB DDL/DML, Tune/Validation/Test 학습은 실행하지 않았다.

다음 작업은 숫자 재검토와 공식 원본 버전 증명을 각각 진행하는 것이다. 공식 증거가 확보된 일부 PDF부터 승인 가능한 사실을 골라, 별도 승인 이력과 기준일별 특징 스냅샷을 만든다. 원본 증명이 해결되기 전까지는 숫자 검증 건수가 늘어도 학습 승인은 0행으로 유지한다. 그 이후에만 기존 코드와 분리된 특징 파일을 만들고 Ridge 연결·성능 평가 여부를 별도로 결정해야 한다.
