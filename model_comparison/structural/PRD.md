## 1. 배경과 목표

멘토 제안: "XGBoost·LightGBM 같은 기성 ML 모델을 튜닝하지 말고, 모델 구조 자체를 새로 설계해서 다듬어라."

지금까지 알게 된 것:
- naive(직전 가격 유지)는 이기기 어렵다. 검증 구간(244 기준일)에서 naive 4.913%, LightGBM p1 4.769%(+2.9%), 앙상블(XGB+LGBM+ARIMA, v2 특징) 4.595%(+6.5%).
- LLM 블라인드 실험(`model_comparison/llm_blind/RESULTS.md`)에서 통한 근거는 알고리즘이 아니라 **구조적 관계**였다:
  1. **도매 → 소매 전달**: 도매가 움직이면 1~2주 뒤 소매가 따라간다(판단 보조 지표 검증에서도 확인: 도매 2주 +5% 뒤 소매 상승 72% vs 평소 44%).
  2. **같은 시기 계절 흐름**: 작년·재작년 같은 시기의 D+1~7 변화(작형 전환, 명절 등).
  3. **도매는 일별 잡음이 커서** 추세를 따라가든 되돌림을 예상하든 naive보다 나빴다. 소매는 오히려 변화폭을 작게 잡았다(평균 예측 1.0% vs 실제 4.1%).
- 그 실험의 사후 분석: "소매만 따라가고 도매는 naive" 규칙이 +7.5%였다. 정답을 본 뒤 고른 규칙이므로 근거로 쓰지 말고 **가설로만** 쓴다.

**목표**: 위 관계를 식으로 직접 담은, 파라미터가 적고 설명 가능한 새 모델을 만들고, 기준서와 같은 조건에서 naive·기존 모델과 비교한다.

**성공 기준**(§6 채점표): 검증 전체에서 기준서 §8.4 관문 통과. 최소 목표는 naive 대비 +5% 이상이고 부트스트랩 하한 > 0이다.

## 2. 범위

### 하는 것
- 직접 설계한 모델 클래스 1개(구조 변형은 설정으로 바꿈), 10개 계열 각각에 따로 학습
- 튜닝 목록(`origins_tune`, 53개 기준일)에서 구조·파라미터 탐색, 최대 40회
- 검증 전체(`origins_validation`)를 **마지막에 1회** 실행하고 결과 보고

### 하지 않는 것
- XGBoost, LightGBM, scikit-learn의 모델 클래스(Ridge·트리 등), statsforecast, optuna 사용 금지. **numpy와 scipy(`scipy.linalg`, `scipy.optimize`)만** 쓴다. 최소제곱, 제약 최적화, 수축은 직접 구현한다.
- 최종 시험 기준일(2025-11-10~) 실행 금지. 실행기가 거부한다.
- 기준서 밖 데이터(v2 반입량, KREI, 주산지 기상) 사용 금지. 1차 버전은 `base_v1 + MARKET + EVENT`까지만 쓴다.
- 커밋, 푸시, PR은 사용자 확인 전에는 하지 않는다.

## 3. 입력 (공통 로더만 사용)

모델은 `tools/runtime.py`의 인터페이스만 받는다. 스냅샷 CSV나 DB를 직접 읽지 않는다.

- `fit(history: TrainingData, seed)`
  - `history.features`: (표본 × 특징) 행렬. 열 이름은 `history.feature_names`이고, `base_v1` 15개 뒤에 MARKET·EVENT 열이 붙는다.
  - `history.targets`: 목표일 실제 가격, `history.horizons`: 1~7, `history.origins`
  - `history.prices`: 창 안 실제 관측 (날짜, 가격). 재학습 기준일까지
- `predict(inputs: OriginInputs) -> list[7]`
  - `inputs.features[h]`: 기준일 d의 시점 h 특징 한 줄
  - `inputs.prices`: d까지 실제 관측
  - 출력은 원 단위 가격 7개이고, 실패하면 None이나 예외

쓸 수 있는 특징(`tools/standard.py`):
- `base_v1`: current, lag1, lag7, lag14, lag28, mean7, mean28, change7, volatility7, price_age, target_weekday, target_season_sin/cos, horizon, days_since_kind_switch
- `MARKET`(d−1까지): counter_price, target_counter_ratio(작형이 다르면 NaN), counter_change7, counter_change28
- `EVENT`(목표일 기준, 미리 확정된 값): days_to_major_holiday, days_from_major_holiday, target_in_event_window, target_prev_day_holiday

계절 유사도 특징은 모델 안에서 `prices`로 직접 계산한다. 예: 기준일 d에 대해 d−364·k (k=1,2,3) 근처 관측에서 h일 뒤까지의 변화율을 구한다. d−364k+h는 항상 d보다 앞이므로 누수가 아니다. `fit`에서는 각 표본 기준일 o에 대해 o 이전 가격만으로 같은 값을 계산한다.

## 4. 모델 설계 (v0 기본형)

목표 변수는 로그 변화율 y = log(실제 가격(d+h) / current)이고, 예측가는 current × exp(ŷ)로 만든다.

### 4.1 소매 계열 (series 1, 8, 10, 9001, 9011)

```
ŷ(h) = k_h · [ a · counter_change7(또는 counter_change28)        # 도매 → 소매 전달
             + b · (log(target_counter_ratio) − 평소 배수)        # 배수 되돌림 (평소 = 학습 표본의 최근 N일 중앙값)
             + c · season_analog(h)                               # 1~3년 전 같은 시기 h일 변화의 가중 평균
             + d · event_term(h)                                  # 명절 영향 기간
             + e · momentum(change7) ]                            # 선택
```

### 4.2 도매 계열 (series 2, 7, 9, 9002, 9012)

```
ŷ(h) = k_h · [ c · season_analog(h) + d · event_term(h) ]         # 기본은 거의 0(naive)
```

### 4.3 파라미터 추정
- a~e는 계열별 최소제곱(시점 통합)으로 추정하고, L2 수축을 직접 구현한다. 수축 강도는 학습 표본의 마지막 20%(시간순)로 고른다. 기준서 §6의 조기 종료 규칙과 같다.
- k_h ∈ [0, 1]은 0 쪽으로 줄이는 계수다. 시점별로 두거나 하나로 묶는다(설정). 역시 학습 표본 마지막 20%로 고른다.
- 결측(NaN, 예: 작형이 달라 ratio가 비는 날)인 항은 0으로 두고, 그 사실을 기록한다.
- 재학습은 주 1회이고 실행기가 관리한다. 같은 주 안에서는 입력만 바뀐다.
- 무작위 요소는 없게 한다. 같은 설정이면 소수점 6자리까지 같아야 한다.

### 4.4 탐색할 구조 변형 (예시, 튜닝 시도로 셈)
- 전달 항: counter_change7 / counter_change28 / 둘 다
- 배수 되돌림 항 유무, "평소 배수" 창 길이(28·91·365일)
- 계절 유사도: 연수(1·2·3년), 가중(균등·최근 우선), 같은 작형일 때만 사용
- k_h: 공통 1개 / 시점별 7개
- 도매: 완전 naive / 계절 항만 / 계절 + 명절
- 학습 창: 기준서 상한 1,825일 안에서 더 짧게(730·1,095일)

## 5. 실행 절차

1. **등록**: `tools/standard.py`의 `MODELS`에 `'struct': ('Structural', 'B')`만 추가한다. 실행기가 모델 이름을 이 목록으로 검사한다. 공통 도구를 바꾸는 것이므로 결과 보고에 "팀 승인 필요"라고 적는다.
2. **코드**: `model_comparison/structural/model.py`(클래스 `StructuralModel`), `config.json`, 변형 설정은 `configs/`
   - `"model": "Structural"`, `"feature_set": "base_v1+MARKET+EVENT"`, `"extra_features": ["MARKET", "EVENT"]`, `"strategy": "pooled_horizons"`, `"target_transform": "log_ratio"`
3. **단위 점검**: `--phase smoke --month 2025-01 --series 1,2,9001`로 오류 없이 도는지 확인한다.
4. **튜닝**(최대 40회, 기본형 포함):
   ```bash
   uv run --extra prices python -m tools.run_backtest --config model_comparison/structural/configs/<변형>.json \
     --phase p1 --origins tune --out runs --record-trial runs/struct-tuning.csv
   ```
   실패한 시도도 기록한다. 튜닝 목록 결과만 보고 다음 변형을 고른다.
5. **확정**: 튜닝 목록 macro MAPE가 가장 좋은 설정을 고정한다. 동률(상대 2% 이내)이면 파라미터가 적은 쪽을 고른다.
6. **검증 1회**:
   ```bash
   uv run --extra prices python -m tools.run_backtest --config model_comparison/structural/config.json \
     --phase p1 --tuning-log runs/struct-tuning.csv
   ```
   검증 결과를 본 뒤에는 설정을 바꾸지 않는다. 바꾸면 그 결과는 "탐색"으로 분류한다.
7. **비교**: `tools.evaluate --compare`로 naive와 기존 결과를 비교한다(가능한 것: ridge, lgbm p1/p2, xgb). 앙상블 수치(4.595%)는 v2 특징을 쓴 것이라 참고로만 적는다.

## 7. 누수 함정 (반드시 피할 것)
- `fit` 안에서 계절 항을 만들 때 표본 기준일 o 이후의 가격을 쓰면 안 된다. `history.prices`에는 재학습 기준일까지의 값이 다 들어 있으므로, 표본마다 o 이전으로 잘라서 계산한다.
- "평소 배수", 정규화 통계, 수축 강도는 그 재학습 시점의 학습 표본으로만 계산한다.
- `experiments_v2/`, `model_comparison/llm_blind/points_*.csv` 같은 다른 실험의 예측이나 정답 파일을 입력으로 쓰지 않는다.
- 검증 결과를 보고 구조를 고치지 않는다. 고치고 싶어지면 사용자에게 보고하고 멈춘다.
- 누수 테스트를 `tests/` 또는 `model_comparison/structural/test_leakage.py`에 둔다. 예: d 이후 가격을 임의로 바꿔도 d의 예측이 같은지 확인한다.

## 10. 결정 사항 (감독자 확정, 2026-11-24 — worker는 아래를 그대로 따른다)

**실행 체계**
- worker는 Claude Code 내장 서브에이전트(Agent 도구, model=sonnet, effort=high)로 띄운다. Orca나 원격은 쓰지 않는다.
- **worktree 격리는 쓰지 않는다.** `data/snapshots/`와 `runs/`가 Git 밖에 있어서 worktree에는 데이터가 없다. 같은 작업 폴더에서 일한다.
- worker는 한 번에 1개만, 순서대로 돌린다. 튜닝 기록 파일을 같이 쓰고, 기준서상 스레드 4개를 유지해야 하므로 병렬 실행은 하지 않는다.
- worker 분담: W1 = 모델 코드 + 누수 테스트 + smoke, W2 = 튜닝 실행(10회 단위로 끊어서 보고), W3 = 검증 1회 + 비교·보고서. 각 worker가 끝나면 감독자가 채점표로 확인한 뒤 다음 worker를 띄운다.

**단계(phase)**
- 실행 단계는 `p1`으로 한다. `p2`는 튜닝 상한이 10회·1시간이라 이 PRD의 40회와 맞지 않는다. MARKET·EVENT를 쓰면 validate가 "1차 순위는 기본 세트만" 경고를 내는데, 이는 예상된 경고이므로 그대로 두고 보고서에 적는다.

**v0 기본형 (튜닝 시도 1번)**
- 목표: log(y/current). 시점은 묶어서 하나의 회귀로 푼다(설계 행렬에 시점별 항 없음). k_h는 시점별 7개.
- 소매 항:
  - 전달: counter_change7
  - 배수 되돌림: log(target_counter_ratio) − 학습 표본 최근 91일 중앙값. NaN이면 0
  - 계절: 아래 정의 참조
  - 명절: target_in_event_window, target_prev_day_holiday 두 지시변수
  - momentum은 넣지 않는다.
- 도매 항: 계절 + 명절만.
- 계절 유사도 season_analog(o, h): k=1,2,3년에 대해 기준점 b = o − 364k 기준 ±3일 안의 가장 가까운 관측 p_b와, b+h 기준 ±3일 안의 가장 가까운 관측 p_bh로 log(p_bh/p_b)를 구한다. 가중치는 0.5·0.3·0.2이고, 없는 해는 빼고 다시 정규화한다. 셋 다 없으면 0. 배추·무는 기준일 o와 b의 작형(days_since_kind_switch로 알 수 없으면 무시)을 맞추지 않는다(v0).
- 추정: 가중 없는 최소제곱 + L2. 람다 후보는 {0, 0.1, 1, 10, 100}(특징 표준화 후). k_h 후보는 {0, 0.25, 0.5, 0.75, 1.0}. 둘 다 학습 표본 마지막 20%(시간순)의 MAPE로 고르고, 고른 뒤 전체 학습 표본으로 다시 맞춘다.
- 학습 창: 1,825일(기준서 상한).
- 예측: current × exp(ŷ). 예측이 NaN이거나 무한이면 current를 반환하지 말고 None을 반환한다(실행기가 실패로 기록하고 policy에서 naive로 대체).

## 13. 1% 규칙 해석 확정과 C3 기준 (계획 결정, 2026-11-24, C2 검증 후)

**해석: 대칭 규칙.** 현재 기준(base)을 후보로 바꾸는 경우는 둘 중 하나다.
- (a) 후보가 base보다 tune macro MAPE 상대 1% 이상 좋다.
- (b) 후보가 base보다 **단순하고**(추정 항이나 파라미터가 적음) 나빠진 정도가 상대 1% 미만이다.

어느 쪽도 아니면 base를 유지한다.
- 근거: 시도 간 차이(4.464~4.510)가 53개 기준일 잡음 범위 안이다. 이 범위에서는 단순한 쪽이 과적합 위험이 적다. 기준서 §8.4의 동률 시 단순성 우선 원칙과도 같은 방향이다.
- C2 소급 적용
  - 3단계: t04(배수 항 제거, −0.35%)가 (b)에 해당하므로 **base = t04_noratio**로 바꾼다.
  - 4단계: t07(계절 1년)은 t01 기준으로 측정한 값이라 새 base와 비교할 수 없다. C3 첫 시도로 "t04 + 계절 1년"을 다시 측정한다.
  - t08(균등 가중)과 t10(명절 마스크)은 단순화가 아니고, t01 대비 개선도 1% 미만이므로 채택하지 않는다.

**C3 시도 목록** (모두 새 base 기준, 한 번에 한 가지만 변경)
- t11: base + 계절 1년(season_years=1, weights [1.0]). 4단계 재측정이며, (b)에 해당하면 채택한다.
- t12: k_h 공통 1개(5단계, 단순화)
- t13: 도매 완전 naive(6단계, 단순화)
- t14: 학습 창 730일, t15: 학습 창 1,095일(7단계)
- t16: 람다 후보 확대(8단계)
- t17: 소매 k 격자 확대 {0, .25, .5, .75, 1, 1.25, 1.5}(retail_k_grid 패치 필요)
- t18~t20: 여기까지 결과를 보고 계획이 조합을 정한다. 미리 만들지 않는다.

**절차 보강** (C1 검증 권고)
- 결과 저장 위치는 항상 `--out runs/struct`로 고정한다. 다른 경로 사용, 결과 폴더 삭제, 검증 구간을 줄인 실행으로 반복 돌리는 것을 금지한다. 위반하면 그 트랙 결과는 무효다.
- `runs/struct/smoke-v0`, `smoke-v0b`의 metrics.json은 지우지 않는다. 대신 같은 폴더에 `DO_NOT_USE.txt`("검증 구간 2025-01 3계열 정확도 포함, 모델 선택·보고에 사용 금지")를 둔다.
- 보고서(README_MODEL.md)에는 PRD와 다르게 구현된 점을 적는다. log1p 전달 항, 열 RMS 정규화, y_clip=1.0과 대체 규칙, 학습 창 경계에서 계절 비교 연도를 버리는 점이다.
- "도매는 사실상 naive" 표현을 정정한다. 양파·깐마늘·무 도매만 해당하고, 대파 도매와 배추 도매는 계절 항을 실제로 쓴다.

## 14. C3 검증 후 보정 (계획 결정, 2026-11-24)

**발견 (verifier C3)**
- §13 판정은 전체 10계열 macro로 했다. 그래서 소매에만 영향을 주는 변경(t04 배수 제거, t11 계절 1년)의 효과가 도매 5계열 때문에 약 절반으로 희석됐다.
- 소매만 보면 t01→t13 누적 악화가 +1.35%로 1%를 넘는다. 소매의 naive 대비 개선은 6.32%에서 5.06%로 줄었다.

**규칙 보정 (이후 적용)**
1. 영향 범위 기준 판정: 소매 항만 바꾸는 변경은 소매 5계열 macro로, 도매 항만 바꾸는 변경은 도매 5계열 macro로 (a)/(b)를 판정한다. 양쪽을 다 바꾸는 변경은 전체 macro로 판정한다.
2. 누적 상한: (b) 채택을 거듭해 처음 base(t01) 대비 해당 범위의 누적 악화가 1%를 넘으면, 그 이후의 (b) 채택은 무효로 한다.
3. 학습 창 축소, λ·k 격자 확대는 "단순화"로 보지 않는다(§13 해석을 명시).

**소급 확인 시도 1회 (t18)**
- t18 = t13(도매 naive) + 소매 항을 t01로 되돌림(배수 항 91일 포함, 계절 3년 0.5/0.3/0.2)
- 판정: 소매 항만 다른 변경이므로 소매 macro로 본다. t18이 t13보다 소매 macro가 상대 1% 이상 좋으면 (a)에 따라 최종 = t18, 아니면 최종 = t13.
- 이 판정 규칙은 t18 실행 전에 여기 적어 고정한다.

**G3·G5 방침**
- 도매를 계열별로 고르는 추가 탐색은 하지 않는다. 잡음 위의 추가 튜닝이 되기 때문이다.
- G3(최대 5/10)와 G5 위험은 "도매는 설계상 naive"라는 결과로 그대로 보고한다.
