# 외부변수 가중치 결정 기록

가격 예측 모델(`XGBOOST_WEIGHTED`)이 외부변수에 가중치를 어떻게 주는지, 그 방식을 어떤 실험과 근거로 정했는지 남긴 기록입니다.
구현은 `app/services/weighting.py`, 특징은 `app/services/exogenous.py`, 결합은 `app/services/price_prediction.py`에 있습니다.
여기 숫자는 모두 **합성 자료** 실험값입니다. 실제 시장에서의 효과는 실데이터 백테스트로만 판단합니다.

## 1. 결론 요약

| 항목 | 결정 | 한 줄 근거 |
| --- | --- | --- |
| 가중치 단위 | 외부변수 **묶음** 5개(시장·기상·달력·계절·거시) | 서로 연관된 변수를 따로 재면 가중치가 흔들림. 전문가 모델 수(학습 시간)도 제한 |
| 가중치 의미 | 묶음 k의 전문가가 '가격만 쓴 예측'을 고치는 양을 얼마나 반영할지(0~1) | 0 = 무시, 1 = 그대로 반영. 설명하기 쉽고 음수·과장을 막음 |
| 결합식 | `예측 = b + Σ w_k (e_k − b)`, `0 ≤ w_k ≤ 1` | 독립적인 신호 둘을 동시에 반영할 수 있어야 함(합 ≤ 1 제약은 기각, 3장 1차 시도) |
| 학습 자료 | 예측 시작일까지 **정답이 확인된 과거 예측 오차**만, 최근 365일 | 미래 정보 누수 방지. 시장 관계가 바뀌면 오래된 오차는 빠짐 |
| 시점(1~7일) | 7개 시점을 시점별 오차 크기로 정규화해 **한 벌의 가중치**로 추정 | 시점별로 따로 추정하면 h=1에서 0, h=2에서 1.0처럼 흔들림 |
| 규제 | Ridge κ ∈ {0, 0.1, 0.3, 1, 3}, 묶음 신호 크기에 비례 | 표본이 적을 때 가중치를 0 쪽으로 줄임 |
| κ 선택·채택 조건 | 시간순 교차검증. 학습이 창의 절반 이상인 두 구간 **모두**에서 가격만 쓴 경우보다 좋고, 합계 오차가 **3% 이상** 줄어야 채택. 아니면 전부 0 | 잡음 묶음에 0.63이 붙던 문제와 공개 시점에 가중치가 꺼지던 문제를 같이 해결(3장) |
| 재추정 주기 | 백테스트·운영 모두 7일마다 | 가격 모델 재학습 주기(7일)와 같게 맞춤 |
| 최종 채택 | 다른 후보와 같은 백테스트에서 이겨야만 선택 | 가중치를 썼다고 강제로 채택하지 않음 |

## 2. 구조

```
가격 특징만 → XGBOOST (기준 예측 b)
가격 + 시장 묶음  → 전문가 e_MARKET   ┐
가격 + 기상 묶음  → 전문가 e_WEATHER  │  과거 실현 오차로
가격 + 달력 묶음  → 전문가 e_CALENDAR ├─ 가중치 w 학습 → b + Σ w_k (e_k − b)
가격 + 계절 묶음  → 전문가 e_SEASONAL │
가격 + 거시 묶음  → 전문가 e_MACRO    ┘
```

| 묶음 | 포함 그룹 | 원천 테이블 | 특징 |
| --- | --- | --- | --- |
| MARKET | WHOLESALE | external_observation(KAMIS 도매) | 전일 도매가, 소매/도매 비율, 7·28일 변화율, 경과일 |
| WEATHER | WEATHER, NATIONAL_WEATHER | 주산지 ASOS, `weather_daily`(ACTUAL) | 주산지 7일 기온·강수·습도·일조, 전국 7일 기온, 28일 강수, 폭염·호우·한파 지수 |
| CALENDAR | CALENDAR, EVENT | KASI 공휴일, `calendar_event`, `price_change_history` | 목표일 공휴일, 설·추석까지/이후 일수, 명절 영향기간 여부, 명절 가격 압력 |
| SEASONAL | SEASONAL | `price_change_history` | 과거 최대 5년 같은 시기(±3일) 같은 시점 변동률의 평균 |
| MACRO | PRODUCTION, FX | `item_production`, `exchange_rate_daily` | 연간 생산량 전년 대비, 원/달러 7·28일 변화율 |

- 극한 기상 지수 = 기간 중 (기준을 넘은 관측소 비율)의 일별 합. 예: 28일 중 3일 동안 관측소 절반이 호우면 1.5. 피해의 넓이와 지속을 같이 본다.
- 묶음이 하나뿐이면 그 전문가는 `XGBOOST_EXT`와 입력이 같으므로 그 모델을 재사용한다.
- 전문가 모델은 수가 많아 14일마다 재학습한다(기준·EXT 모델은 7일). 측정값: XGBoost 1회 학습 약 0.09초,
  묶음 5개·1,200일 합성 자료에서 품목당 예측 약 50초(전문가 추가 전 약 25초).

## 3. 결정 로그

### 실험 자료

| 이름 | 내용 | 정답 |
| --- | --- | --- |
| 시나리오 A (신호) | 도매가가 소매가를 4일 앞섬 + 추석 전 14일간 최대 +12% 상승. 전국 기상·환율·생산량은 무관한 잡음 | MARKET·CALENDAR에 가중치, 나머지 0 |
| 시나리오 B (잡음) | 도매가 신호가 약하고 잡음이 큼(동행 50% + 2일 선행 50%, 도매가 관측 오차). 명절 효과 없음 | 가격만 쓴 모델과 같거나 비슷해야 함 |

1,200일(주말 결측), 평가 지표는 최종 평가 구간 MAPE(%). 오프라인 비교는 백테스트에서 기록한 실현 오차를 그대로 재생해 결합 규칙만 바꿔 계산했다(뒤 1/3 구간).

### 1차: 시점별 가중치 + 합 ≤ 1(볼록 결합) + 교차검증 1% 기준

| A 평가 MAPE | 값 |
| --- | --- |
| LAST_PRICE / XGBOOST | 2.901 / 2.357 |
| XGBOOST_EXT | **1.949** |
| XGBOOST_WEIGHTED | 2.111 |

- 문제 1: 시점마다 가중치가 크게 흔들림. h=1은 MARKET 0·MACRO 0.33, h=2는 MARKET 1.0.
- 문제 2: 합 ≤ 1이면 '도매가 수정'과 '명절 수정'을 동시에 온전히 반영할 수 없음(평균만 가능).
- 결정: 합 제약을 없애고 묶음별 0~1 상자 제약으로 변경. 같은 정보의 묶음이 둘이면 최소제곱이 몫을 나누므로 이중 반영은 생기지 않음
  (단위 테스트: 같은 전문가 둘의 가중치 합 ≈ 1). 7개 시점은 시점별 오차 RMS로 정규화해 묶어서 추정.

### 2차: 상자 제약 + 시점 통합

- A: 최종 가중치 MARKET 0.47, CALENDAR 0.74, WEATHER 0, SEASONAL 0, MACRO 0.04. 안정적이고 정답과 맞음.
- **B: WEATHER(순수 잡음)에 0.63.** 평가 MAPE: XGBOOST 3.805 < WEIGHTED 3.843 < EXT 3.881.
- 원인: 서로 다르게 학습된 두 모델을 평균하면 분산이 줄어 오차가 약간 줄어든다. 이 효과가 '변수의 효과'처럼 가중치에 잡혔다.
  또 이웃한 날·시점의 오차는 겹쳐 있어 표본 1,130개가 실제로는 훨씬 적은 정보량이다.

### 3차: 채택 조건 비교(오프라인 재생)

| 규칙 | A 결합 MAPE (기준 2.237) | A 공개 시점 가중치 | B 결합 MAPE (기준 3.039) | B 공개 시점 가중치 |
| --- | --- | --- | --- | --- |
| 2차 그대로(1% 기준) | 2.003 | MARKET .47 CAL .74 | 3.083 | WEATHER .63 등 |
| 3구간 모두 개선 | 1.902 | **모두 0(꺼짐)** | 3.051 | 0 |
| 3% 기준 | 2.003 | — | 3.041 | — |
| 3구간 모두 개선 + 3% | 1.902 | **모두 0(꺼짐)** | 3.039 | 0 |
| 묶음별 사전 선별 | 2.069 | — | 3.107 | — |
| 전진 선택 | 1.917 | MARKET .90만 | 3.110 | 0 |
| **뒤 2구간(학습 ≥ 절반) 모두 개선 + 3%** | **1.848** | **MARKET .57 CAL .89** | 3.048 | **0** |

- '모든 구간 개선' 규칙에서 공개 시점 가중치가 꺼진 원인: 첫 구간은 학습 표본이 창의 1/4뿐이라 κ=0에서 과적합(구간 오차 211 > 기준 191)했다.
  실제 운영은 창 전체로 학습하므로 학습이 절반 미만인 구간은 운영과 너무 다르다. → 4구간 중 뒤 2구간만 평가.
- 전진 선택은 CALENDAR를 놓쳤고(추석이 없는 구간에서는 이득이 없음) B에서 잡음을 골랐다. 묶음별 사전 선별도 B에서 잡음이 남았다.
- **채택: 창을 시간순 4구간으로 나눠 [1,2]→3, [1,2,3]→4를 평가. 두 구간 모두 기준보다 좋고 합계 3% 이상 개선될 때만 가중치 사용.**
  A에서 결합 오차가 가장 낮고, 공개 시점 가중치가 정답(시장·달력)과 일치하며, B에서는 공개 가중치가 0이다.

### 최종 엔드투엔드(실제 `predict` 실행)

| 시나리오 | 선택 모델 | 평가 MAPE | 공개 가중치 | 평가 구간 평균 가중치 |
| --- | --- | --- | --- | --- |
| A | XGBOOST_EXT | EXT 1.949, WEIGHTED 2.118, XGBOOST 2.357 | MARKET .57, CALENDAR .89, 나머지 0 | MARKET .44, CALENDAR .93, MACRO .01 |
| B | XGBOOST_WEIGHTED(= XGBOOST) | WEIGHTED 3.805 = XGBOOST 3.805, EXT 3.881 | 모두 0 | 모두 0 |
| 테스트 자료(도매 5일 선행 + 무관한 환율) | XGBOOST_EXT | EXT 1.655, WEIGHTED 1.686 | MARKET 1.0, MACRO 0.0 | MARKET 1.0, MACRO 0.002 |

- A에서 EXT가 이긴 이유: 명절 상승이 가격 수준에 곱해지는 상호작용이라 모든 특징을 한 모델에 넣는 쪽이 유리했다.
  두 후보가 같은 백테스트로 경쟁하므로 이 경우 EXT가 선택된다. 가중 모델은 B처럼 잡음 변수가 많을 때 가격 모델을 망치지 않는 안전장치 역할을 한다.
- 가중 모델은 실현 오차가 쌓이기 전(백테스트 초반)에는 가중치가 0이라 선택 구간에서 불리하다. 의도된 보수성이다.

## 4. 명절 가격 압력(`event_item_weight`, EVENT 특징)

`exogenous.event_weight` 하나로 예측 특징과 `event_item_weight`(LEARNED) 적재에 같이 쓴다.

1. 해마다 효과 = 명절 영향기간(D−14 ~ 종료 D+3) 기준일의 7일 변동률 평균 − 직전 60일 평균.
   직전 평소 흐름을 빼서 계절 추세를 명절 효과로 착각하지 않게 한다.
2. 연도 평균을 James–Stein 계수 `max(0, 1 − se²/평균²)`로 0 쪽으로 줄인다. 해마다 방향이 엇갈리면 0이 된다
   (테스트: 매년 +8%p → 0.66, +8/−7%p 교대 → 0).
3. `tanh(효과 / 10%p)`로 −1~1에 담는다(스키마의 weight 범위). 10%p 차이 ≈ 0.76.
4. 영향기간의 7일 뒤 가격까지 확인된 명절만, 2개 연도 이상일 때만 계산한다. MANUAL 행은 덮어쓰지 않는다.

## 5. 시점 규칙(누수 방지) 근거

| 원천 | 규칙 | 근거 |
| --- | --- | --- |
| 전국 기상·환율 | 1일 지연 | 기존 도매가·ASOS와 같은 보수적 가정 |
| 과거 같은 시기 변동률 | 기준일 b, 시점 h 값은 b+h ≤ 예측 시작일일 때만 | 그 변동률을 만든 가격이 확인된 뒤에만 사용 |
| 연간 생산량 | Y년 값은 Y+1년 6월 30일부터 | KOSIS는 최종 수정일만 주고 최초 공표일이 없음. 가정이며 기관 공표 일정으로 확인 필요 |
| 명절 기간 | 목표일 값 사용, 공휴일 미수집 연도는 결측 | 법정공휴일은 미리 확정. 미수집을 '명절 아님'으로 단정하지 않음 |
| 단기예보 | 사용 안 함 | 과거 발표본이 없어 백테스트 불가 |

## 6. 한계

- 모든 수치는 합성 자료입니다. 실제 대파 등에서 어떤 묶음이 얼마를 받는지는 실데이터 백테스트 결과(`price_model_run.metrics.weighting`)로 확인합니다.
- 가중치는 '과거 예측 오차를 줄인 결합 비중'이지 가격에 대한 인과 효과나 영향 방향이 아닙니다. 화면에도 그렇게 표기합니다.
- 상수(3%, 365일, 4구간, κ 후보, EVENT_SCALE 10%p, 생산량 공개일)는 위 실험과 기존 기준(모델 선택 1% 규칙, 7일 재학습)에 맞춘 값입니다.
  실데이터가 쌓이면 같은 방식으로 재검토합니다.

## 7. 결과 확인 위치

- `price_model_run.metrics.weighting`: `weights`(공개 가중치), `kappa`(None이면 가격만), `samples`, `blocks`, `blockFeatures`, `evaluationMeanWeights`
- `/api/v1/prices/items/{itemId}/factors`: 가중 모델이 선택되면 '외부변수 가중치' 항목과 각 원천의 `modelWeight`
- `event_item_weight`(weight_source='LEARNED'): 품목별 설날·추석 가격 압력
