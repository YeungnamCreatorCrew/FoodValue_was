## 2. 내 모델 만들기

`model_comparison/<내 모델>/model.py`에 클래스 하나. 예시는 `tools/baselines.py`.

```python
class MyModel:
    def __init__(self, **params):        # 설정 파일의 params가 그대로 들어옴
        self.params = params

    def fit(self, history, seed):        # 주 1회 호출
        X = history.features             # numpy (표본 수 × 15), 열 이름 history.feature_names
        y = history.targets              # 목표일 실제 가격(원)
        h = history.horizons             # 1~7
        ...

    def predict(self, inputs):           # 매 기준일 호출
        # inputs.features[h] = 시점 h(1~7)의 특징 한 줄
        return [가격1, ..., 가격7]       # 원 단위 7개. 실패는 예외나 None
```

- 특징 15개: `current, lag1, lag7, lag14, lag28, mean7, mean28, change7, volatility7, price_age, target_weekday, target_season_sin, target_season_cos, horizon, days_since_kind_switch`
- 계열 모델(AutoARIMA): `history.prices`, `inputs.prices` = 기준일까지 실제 관측 (날짜, 가격) 목록
- 변화율·로그 같은 변환, 시점별 모델 / 시점 통합 모델 선택은 모델 안에서 자유 (설정 파일에 기록)
- 스냅샷 CSV·DB를 직접 읽지 않는다. 주어진 것만 쓴다.
- 결정적 실행 옵션 필수: XGBoost `tree_method="hist", n_jobs=4`, LightGBM `deterministic=True, force_row_wise=True, num_threads=4`, AutoARIMA `n_jobs=1`, Ridge `solver` 명시(`"auto"` 금지)

## 3. 설정 파일

`model_comparison/<내 모델>/config.json` 예:

```json
{
  "model": "LightGBM",
  "owner": "B",
  "class": "model_comparison.lightgbm.model:MyModel",
  "params": {"num_leaves": 31, "learning_rate": 0.05, "n_estimators": 500,
             "deterministic": true, "force_row_wise": true, "num_threads": 4},
  "feature_set": "base_v1",
  "extra_features": [],
  "target_transform": "log_ratio",
  "strategy": "direct_per_horizon",
  "seed": 42
}
```

`model`은 `XGBoost`, `LightGBM`, `AutoARIMA`, `Ridge` 중 하나. 나머지 항목(실험 id, git SHA 등)은 실행기가 채운다.

## 4. 실행

```powershell
# 빠른 점검 (한 달, 계열 2개). 결과는 runs/ (깃에 안 올라감)
uv run --extra prices python -m tools.run_backtest --config model_comparison/lightgbm/config.json --phase smoke --month 2025-01 --series 1,9001 --out runs

# 튜닝 시도 1회 = 튜닝 목록(주마다 1개, 약 53개 기준일). 시도마다 기록 파일에 한 줄 추가. 최대 40회
uv run --extra prices python -m tools.run_backtest --config model_comparison/lightgbm/config.json --phase p1 --origins tune --out runs --record-trial runs/lgbm-p1-tuning.csv

# 1차 제출: 설정을 정한 뒤 검증 전체(약 244개 기준일 × 10계열) + 튜닝 기록
uv run --extra prices python -m tools.run_backtest --config model_comparison/lightgbm/config.json --phase p1 --tuning-log runs/lgbm-p1-tuning.csv
```

- 제출 결과는 `experiments/lgbm-p1-YYYYMMDD-01/`에 생긴다. 이 폴더를 PR로 올리면 CI가 형식을 검사한다.
- 실행이 끝나면 화면에 macro MAPE, naive 대비 개선율, 계열별 결과, 검증 관문 1~5(O/X)가 나온다.
- 최종 시험 기간(2025-11-10~)은 `--phase test`에서만 쓸 수 있다. 다른 단계에서 쓰면 실행 전에 막힌다.

## 5. 모델끼리 비교 (1차 결과가 모이면)

```powershell
uv run --extra prices python -m tools.evaluate --compare experiments/xgb-p1-... experiments/lgbm-p1-... experiments/arima-p1-... experiments/ridge-p1-... --out comparison.json
```

`policy`(실패 시 naive로 대체) · `model_only` · `common_success` 세 결과, 순위, 상대 2% 미만 동률이 나온다. 순위는 `policy` macro MAPE 기준.

## 결과 상태 코드

| 상태 | 뜻 |
|---|---|
| `OK` | 정상 |
| `NO_INPUT` | 자료 부족(학습 관측 400개 미만, 최신 관측이 7일보다 오래됨, 최근 28일에 빈 값) |
| `FIT_FAILED` | fit에서 오류 |
| `PREDICT_FAILED` | predict에서 오류, 7개가 아님, None |
| `INVALID_VALUE` | NaN·무한·0 이하 |
| `TIMEOUT` | 재학습 기준일 600초, 예측만 60초 초과 |

성공률이 99% 미만이면 채택 기준 4번 미달이다.
